# FRED/ALFRED como fuente macro para PAPER 14D

**Decisión: FRED_INSUFFICIENT como proveedor macro único.** No se implementa `FredMacroDataProvider` ni se activa FRED en runtime: la API no proporciona los campos necesarios para convertir con seguridad un release en un evento intradía del contrato `MacroDataProvider`. La decisión se basa en documentación oficial; no se llamó a FRED ni se solicitó una clave.

| Criterio | Evidencia oficial | Resultado para el gate |
| --- | --- | --- |
| Awareness de releases futuros | [`fred/releases/dates`](https://fred.stlouisfed.org/docs/api/fred/releases_dates.html) y [`fred/release/dates`](https://fred.stlouisfed.org/docs/api/fred/release_dates.html) permiten `include_release_dates_with_no_data=true`; las fechas proceden de la fuente y no aseguran cuándo FRED tendrá los datos. | Parcial, a nivel de **día**. |
| Actual publicado | [`fred/series/observations`](https://fred.stlouisfed.org/docs/api/fred/series_observations.html) devuelve valores de series; faltantes aparecen como `.`. | Disponible para series seleccionadas y después de su publicación en FRED; no equivale al comunicado en tiempo real. |
| Consenso/forecast | Los esquemas de release date y observation muestran fecha, release ID/nombre, vintage y valor; no campo de consenso. | `null`; no sintetizar. |
| Previous | Se pueden consultar observaciones anteriores con un vintage histórico apropiado mediante `realtime_start/realtime_end` o `vintage_dates`. | Parcial; no es el “previous” de un calendario de noticias y requiere mapeo explícito de serie y período. |
| Importancia/severidad | No es campo de los endpoints de release date u observations. | `null`/`UNKNOWN`; no asignar HIGH por nombre. |
| Hora exacta/zona | Release dates y vintages son `YYYY-MM-DD`, sin hora ni zona. | **Ausente**. No convertir a medianoche ni a una supuesta hora de release. Bloquea un gate de ciclos de 15 minutos. |
| Timestamp de fuente/update | El endpoint de release dates puede incluir `release_last_updated` al solicitar fechas sin datos; [`fred/series`](https://fred.stlouisfed.org/docs/api/fred/series.html) tiene `last_updated` por serie. [`ALFRED real-time periods`](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html) describe conocimiento por fecha. | Metadatos parciales; no prueban el instante intradía en que un valor o revisión estuvo disponible al mercado. `fetched_at` local solo prueba captura. |

Los releases FRED abarcan series estadounidenses que permiten investigar CPI, empleo, GDP y ventas minoristas, pero se debe verificar el release ID y las series concretas antes de mapearlos. La API documentada no demuestra cobertura completa de declaraciones de política FOMC ni calendario de decisiones del ECB. El [calendario FOMC oficial](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm) y el [calendario ECB oficial](https://www.ecb.europa.eu/press/calendars/mgcgc/html/index.en.html) son fuentes distintas. Tampoco se debe inferir que una serie del área euro en FRED cubra anuncios ECB.

Una clave registrada de FRED es obligatoria para estos endpoints según la [documentación de API keys](https://fred.stlouisfed.org/docs/api/fred/api_key.html); no se documenta un entitlement adicional para los endpoints examinados. Obtenerla no repara la falta de hora, consenso, severidad ni anuncios de política. Por ello **no se solicita `FRED_API_KEY` para decidir**.

Un híbrido de fuentes oficiales puede cubrir **parte del calendario futuro sin scraping frágil**: [BLS publica un feed iCalendar](https://www.bls.gov/schedule/news_release/empsit.htm) para CPI/empleo; [BEA ofrece ICS y JSON](https://www.bea.gov/news/schedule/icalendar) para GDP/PCE; [Eurostat ofrece ICS](https://ec.europa.eu/eurostat/en/web/products-eurostat-news/w/wdn-20260105-1) para euro indicadores. Los calendarios oficiales [Fed](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm), [ECB](https://www.ecb.europa.eu/press/calendars/mgcgc/html/index.en.html) y [Census](https://www.census.gov/economic-indicators/calendar-listview.html) podrían completar FOMC/ECB/retail, pero sus formatos y precisión deben certificarse por separado antes de automatizarlos. Ese híbrido tampoco garantiza consenso ni severidad de mercado: esos campos deben permanecer nulos. No se selecciona ni implementa automáticamente en esta evaluación.

Seguridad temporal: los tests `test_fred_alfred_safety.py` rechazan fechas de release sin hora, valores revisados sin instante probado de publicación y cualquier `source_timestamp`, `received_at` o `fetched_at` posterior a `as_of`. ALFRED permite reconstrucción por **fecha** de vintage; una revisión del mismo día no se considera conocida intradía por inferencia.
